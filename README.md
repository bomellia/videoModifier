# Video Modifier

ブラウザ内のFFmpeg WebAssemblyで、動画のカット・部分倍速・回転を行う静的サイトです。
実際に使用するアプリは `docs/` にあります。動画はサーバーへアップロードしません。

## 起動

プロジェクトのルートで、Pythonなどの静的HTTPサーバーを起動します。

```sh
python -m http.server 8765 --bind 127.0.0.1 --directory docs
```

`http://127.0.0.1:8765` をブラウザで開いてください。`file://` ではWorkerを読み込めません。
バンドル済みのFFmpegを使用し、実行時のCDN依存はありません。npm installやビルドは不要です。

## 編集方法

1. 動画を選び、カット位置の解析が完了するまで待ちます。
2. 動画を分割したい位置へシークし、「再生位置で分割」を押します。
3. 不要な区間を「削除」してカットします。削除した区間は先頭の空白から順に戻せます。
4. 「残す区間」で区間を選び、開始・終了スライダーや再生速度を調整します。
5. 「編集結果をプレビュー」で残す区間と速度を確認し、「高速書き出し」でMP4を保存します。

速度は0.5・1・1.5倍と、2〜10倍の整数倍率。区間は元動画の時間順に接続し、最大100区間です。
各区間に、元動画の範囲に加えて編集後の開始・終了時刻と区間の長さを表示します。カットや速度変更に合わせて累積時間を更新します。
スライダーや分割位置は最寄りのキーフレームに合わせ、実際に使用する位置を表示します。
スライダーによる他区間との重複はエラーとし、元の範囲に戻します。

## 書き出しの仕組み

- `docs/editor.js` が編集計画の検証、キーフレーム解析、FFmpegコマンドの生成を担当します。
- 解析は圧縮パケットを走査し、キーフレームだけCRC出力します。映像をデコード・再圧縮しません。
- 元ファイルは動画選択時に一度だけWASMへ読み込み、繰り返しの書き出しで再利用します。
- 映像は常に `-c:v copy`。倍速は `setts` でPTS・DTSを別々に変更し、Bフレームの表示順序を保持します。
- 複数区間をつなぐ場合は共通のデコード先行時間を使い、速度の境界でDTSが逆行するのを防ぎます。
- カット境界で読み込まれた余分な映像パケットは除外します。
- 以前のトリムで残された先頭より前のデコード用パケット（MP4のプリロール）も保持します。
- 元動画の回転情報を保持し、追加回転を適用します。プレビューは回転後も表示枠に収まるよう調整します。
- 通常速度だけなら音声もコピー。倍速があり音声を残す場合だけ、音声に `atempo` を適用してAACへ変換します。
- 音声変換では区間の長さを揃えてから連結し、一度だけエンコードします。音声なしを選べば変換は不要です。
- 同じ速度で隣接する区間は統合します。通常速度の単一区間は、従来同様に1回のコピーで書き出します。
- 処理中の編集は無効化し、編集後は古いダウンロードリンクを無効化します。作業ファイルと不要なObject URLは解放します。

## 制約

- 任意フレームでの正確なカットではありません。キーフレームが少ない動画では切断位置が大きく動きます。
- MP4/H.264/AACを中心に検証しています。入力コーデックがMP4に入らない場合や時刻が不整合な場合はエラーになります。
- オープンGOPなど、キーフレームのフラグだけで独立再生を保証できない素材は境界で乱れる可能性があります。
- 高倍率ではフレームを間引かず表示間隔を詰めるため、再生機器によってはコマ落ちします。出力は可変フレームレートになります。
- 通常速度の複数カットでは、区間からはみ出す音声パケットを除外するため、接続箇所に音声1〜2パケット程度の隙間が生じる場合があります。
- MP4の時刻丸め・フレーム期間の扱いにより、映像末尾の長さには元動画の1フレーム程度の差が生じる場合があります。
- 音声付き倍速は音声変換の分だけ時間が加わります。複数区間ではコピーと連結のI/Oも増えるため、従来と同じ所要時間を保証しません。
- プレビューは元動画のシークとplaybackRateを使う簡易確認です。境界の再生は書き出した動画ほど滑らかではありません。
- メモリ使用量は元動画・区間ファイル・出力サイズに依存します。1GBを超える入力は受け付けませんが、それ以下でも端末の空きメモリ次第で失敗します。
- フレーム単位のカット、映像エフェクト、一定fpsへの変換、区間の並べ替えには対応していません。

## 検証

Node.js 24以降。結合テストではfixture生成と独立した出力検査にネイティブの `ffmpeg` / `ffprobe` を使用します。
**編集処理自体はアプリに同梱したFFmpeg 5.1.4のWASMで実行**します。

```sh
node --test --test-isolation=none tests/editor.test.mjs
node tests/export.integration.mjs
```

通常トリム、複数カット、部分倍速、スロー、無音、回転、繰り返し実行、入力の差し替え、失敗後の再試行を検証します。
元映像の圧縮パケットのSHA-256一致、フレーム数、PTS/DTS、音声と映像の長さ、作業ファイルの解放も確認します。
生成物はGit無視対象の `tests/.tmp/` に保存します。

ルートの `index.js` とGit無視対象の `video-trimmer/` は従来の試作版です。
